# Word types (issue #75)

Generated by `node scripts/classify-names.mjs` (from `dictionary-app/`) from
`data/bible-indices/verses.json` and `files/motu_vocabulary.csv`. Re-running it
gives the same files. The script's header comment explains the rule.

| File | What it is |
|------|------------|
| `names.tsv` | The words tagged `word_type = 'name'` by migration `20261025100000_tag_bible_names.sql`, with evidence (how often each is capitalised mid-sentence and at a sentence start, and one example verse). |
| `sentence-start.json` | Words never written in lower case but capitalised only where a sentence may start. Left as vocabulary: some are ordinary words, some are names. An admin can re-tag them on the word page. |
| `near-misses.json` | Words that are almost always capitalised. Only `israel` and `mose` are tagged (their lower-case uses are typos); the rest are Motu words that share a name's spelling. |
| `english-review.json` | **For a speaker to review (Claire).** Tokens in the Motu text that look like English words (king, queen, put, set...). Nothing is changed for them: they stay vocabulary until a speaker decides. |
| `summary.json` | Counts. |

Corrections after the migration are made on the word page (admin: "Mark as
name / place" / "Mark as vocabulary") and logged to `moderation_log` as
`set_word_type`. The migration skips any word with such an entry, so it never
undoes a correction.
